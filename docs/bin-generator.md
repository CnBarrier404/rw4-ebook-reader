# TXT → Watch 4 书籍安装表盘

本工具根据用户提供的三个 BIN 样本重建资源容器，使用自己的 Lua 安装脚本。输入仅支持 TXT，默认目标包名取自 `src/manifest.json`（当前为 `com.cnbarrier.ebook`），不包含小说封面、书名图片或背景图。表盘预览和安装按钮等固定 UI 图片沿用样本。

## 使用

需要 Node.js 18 或更新版本；打包工具本身只用 Node 内置模块，不需要额外安装依赖。在仓库根目录执行：

```powershell
npm run pack-book -- --input "D:\Books\示例.txt" --output "D:\Books\示例.bin"
npm run pack-book -- --input "D:\Books\示例.txt" --output "D:\Books\示例.bin" --package com.example.reader --title "示例书名" --force
npm run pack-book -- --input "D:\Books\GBK小说.txt" --output "D:\Books\GBK小说.bin" --encoding gb18030
npm run inspect-bin
npm run inspect-bin -- --input "D:\Books\示例.bin"
```

默认用输入文件名去掉 `.txt` 作为书名。已存在的输出文件需要 `--force` 才能覆盖。包名和书名会做路径、Lua 字符串和 shell 命令字符检查；不合法时请用 `--title` 改名。工具不接受封面参数或 EPUB、PDF 等输入。

自动识别 UTF-8、UTF-16LE、UTF-16BE 的 BOM；无 BOM 默认严格 UTF-8，旧中文文本请显式指定 `--encoding gb18030` 或 `gbk`。正文统一输出为 UTF-16LE + `FF FE` BOM，保留换行与文字，不做章节拆分。拒绝空白文本、解码错误和非文本控制字符。输入上限暂定 4 MiB，是本工具的保守限制，不代表固件或手机工具的已证实容量。

## 安装和阅读器对接

1. 将生成的 BIN 传到手机，在表盘自定义工具中选择 Redmi Watch 4，使用现有 BIN 表盘安装入口。
2. 在手表上打开安装表盘，点击底部安装按钮。安装器分阶段执行目录创建和复制，再逐块比较目标文件与原始正文，验证一致后显示成功图片。界面不展示书名，安装前通过 BIN 文件名区分书籍。
3. 导入目标为 `/data/quickapp/mass/<包名>/<书名>.txt`。同包名、同书名会覆盖原正文；新书名产生另一文件。移除了原脚本的“五个文件”限制，这不是对设备容量的保证。
4. 自建阅读器需要枚举并读取该目录对应的应用文件空间，按 UTF-16LE 解码。当前应用仍是空白入口，尚未实现书架、文件读取或阅读界面，也未验证该物理目录与 Vela 文件 URI 的映射。成功生成 BIN 不会自动给空白应用增加阅读功能。

目前已验证主机端结构、文本往返、原样本逐字节重建；**尚未验证手机工具是否接受新 BIN，以及手表固件是否允许新包名目录写入**。Lua API 与命令用法参考样本；新增的二进制分块读取验证仍需实机检查。复制中断可能留下不完整文件，需重新安装；尚未实现原子替换。固定表盘 ID 沿用样本 `267130133`，连续安装可能替换同 ID 的安装表盘，其具体行为待测。

## 样本结论

| 文件               |  字节数 | SHA-256                                                            |
| ------------------ | ------: | ------------------------------------------------------------------ |
| ebook.bin          | 3209969 | `ca24ed72e6dfc0bf8c5adf4e70f38dc1346c811feff5df238accd1dec5f7a4ae` |
| ebook2.bin         | 3249220 | `986049b4da55bf3cd3c35626001fce5b1ce9b8872f170cf531ef40ba698170ee` |
| ebook2_with_bg.bin | 3249220 | `de7b956cac3df95ecbf014f23f49f4da38b819b19c9c5610cf9db66d55d8aafc` |

三个样本都包含 10 个资源。`ebook.bin` 的 `lua/main1.lua` 从 `0xBB9C` 开始存放资源名，脚本正文从 `0xBBA9` 开始，其中目标文件路径、文件计数路径和 `mkdir` 命令三处固定使用 `com.givemefive.ebook`。正文位于 `lua/dic`，并非 ZIP；文件复制时才改为小说的 `.txt` 文件名。

`ebook2.bin` 和 `ebook2_with_bg.bin` 的差异仅在 `lua/bg.bin` 的数据，其他记录与头部一致。两者 `fm.rle` 和 `name.rle` 均为相同的 30 字节占位图。不能把 `with_bg` 文件名理解为是否包含背景资源：两个文件都包含它，像素数据不同。

## 观察到的二进制布局

所有数值为小端；这是对三个样本的逆向结果，未据此宣称支持其他表盘格式。

| 位置                | 含义                                                                                      |
| ------------------- | ----------------------------------------------------------------------------------------- |
| `0x00`              | 魔数 `5A A5 34 12`                                                                        |
| `0x20`、`0xAC`      | 预览区绝对偏移                                                                            |
| `0xD8`              | 资源个数（uint32）                                                                        |
| `0xDC`              | 资源索引起点，样本为 `0x110`                                                              |
| `0xE4/EC/F4/FC/108` | 索引末尾哨兵位置                                                                          |
| `0x110` 起          | 每项 16 字节：uint32 `0x05000000 + 序号`、uint32 零、uint32 记录绝对偏移、uint32 记录总长 |
| 索引之后            | 16 字节哨兵，随后为预览区                                                                 |
| 预览区              | 12 字节头，其 `+8` 的 uint32 是其后预览数据长度                                           |
| 文件记录            | 3 字节内容长度 + 1 字节文件名长度 + 16 字节零 + UTF-8 文件名 + 内容；文件名无 NUL 结尾    |

生成器将资源数改为 7，重算索引、预览和记录偏移及所有长度。预览数据保持原样。样本在最后一个资源末尾结束，没有观察到额外文件尾校验段；未完全解释的固定头字段保留，不据此断言任意固件都无校验或签名要求。

## 源码与资源来源

- `tools/bin/format.mjs`：严格解析已观察布局、编码和结构检查。
- `tools/bin/book.mjs`：TXT 解码、输入检查、资源组装。
- `tools/installer.lua`：本项目安装脚本。
- `tools/assets/header-preview.bin`：从用户提供的 `ebook.bin` 提取 `[0, 0xBB88)`，仅有外层头、旧索引和固定预览，编码时重建旧索引。
- `tools/assets/{install,error,runing,success,title}.rle`：从同一样本提取的固定 UI 图片。

仓库不包含样本小说正文、原 Lua 脚本或小说背景图片。保留资源来源于用户样本，未确认上游再分发许可；这些资源不是本项目原创。工具当前依赖此已知外壳，不是从零实现的通用表盘设计器。
